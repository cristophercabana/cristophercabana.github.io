CrackMe Writeup #1 - Reversing

I am documenting my journey in reverse engineering through CTF challenges and crackmes.

Challenge Information

Challenge: CrackMe - Password Validation

Difficulty: Easy

Category: Reversing

Initial Analysis

When running the program, entering an incorrect password shows the message "Password Trash". This suggests that the program validates user input against an internal value.

String Analysis

Cheat Engine was used to search for the string "Password Trash" in memory. A static reference (highlighted in green) was found, indicating that the string is stored in the binary.

Following the references led to the following loop:

mov al, [ecx]
inc ecx
test al, al
jne ...

This loop iterates through a string byte by byte until it finds a null terminator (0). This indicates that it is part of an internal routine and not the actual validation logic.

Identifying the Main Flow

By following the stack trace, the relevant function inside the binary at "parol.exe+10CC" was reached.

Validation Logic Analysis

call GetDlgItemTextA
push "SuperPass"
lea eax, [ebp-104]
push eax
call lstrcmp
or eax, eax
jne fail

Interpretation

  • GetDlgItemTextA: retrieves the user input and stores it in memory
  • lea eax, [ebp-104]: gets the address of the buffer
  • push "SuperPass": prepares the comparison string
  • lstrcmp: compares both strings
  • jne: jumps if they are different

Conclusion

The correct password is:

SuperPass

When entered, the program displays the message "Password Good".

Notes

This challenge demonstrates a basic password validation mechanism using a direct string comparison. It is a good introduction to reversing simple binaries and understanding how user input is processed and validated.
